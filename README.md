# DormWash 🍃

DormWash — це екологічний мобільний застосунок для оптимізації прання у студентському гуртожитку. Основна мета проєкту полягає у збереженні ресурсів (води та електроенергії) шляхом підбору раціональних режимів прання та ведення локальної історії.

Завдяки вбудованому ШІ-помічнику застосунок аналізує параметри одягу (тип тканини, колір, рівень забруднення та вагу) і генерує рекомендації щодо оптимального екорежиму, температури, тривалості циклу та дозування прального засобу.

## Реалізований функціонал (Лабораторні роботи 2–4)
- **Генерація екорежиму (Лаб 2–3):** користувач вводить тип тканини та вагу одягу (`weight_kg`, до 20 кг) у мобільному застосунку, дані валідуються на клієнті та сервері, після чого бекенд передає запит у модель ШІ (`gemini-3.5-flash-lite`) та повертає структуровану рекомендацію.
- **Knowledge Base та Vibe Coding (Лаб 3):** у папці `/docs` зібрано архітектурну документацію, API-контракт, сценарії тестування та правила роботи для coding agent (`ai-instructions.md`).
- **Локальна історія прань (Лаб 4 — базовий рівень):** реалізовано постійне зберігання успішних запитів і результатів у локальній базі даних SQLite (`dormwash_history.db`, шар `WashStorage.kt`). Додано екран списку історії (`HistoryActivity`) у зворотному хронологічному порядку, обробку порожнього стану, екран деталей (`DetailActivity`), а також видалення окремого запису й очищення всієї історії з підтвердженням.
- **Офлайн-черга та повторна відправка (Лаб 4 — підвищений рівень):** за відсутності зв'язку із сервером запит автоматично зберігається локально зі статусом `очікує`. Після відновлення мережі користувач може вручну надіслати його з екрана деталей із відстеженням статусів (`очікує` → `надсилається` → `готово` / `помилка`) та захистом від повторного одночасного надсилання.

### Технологічний стек
- **Mobile:** Android (Kotlin), Retrofit, Coroutines, Gson, SQLite (`SQLiteOpenHelper`).
- **Backend:** Python 3.10+, FastAPI, Pydantic, python-dotenv.
- **AI:** Google Gemini API (`gemini-3.5-flash-lite`).

## Інструкція із запуску (Backend)

1. **Створіть та активуйте віртуальне середовище:**
   ```bash
   python -m venv venv
   # Для Windows:
   venv\Scripts\activate
   # Для Mac/Linux:
   # source venv/bin/activate
   ```

2. **Встановіть залежності:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Налаштуйте змінні середовища:**
   Створіть файл `.env` у теці `backend` та додайте свій ключ API:
   ```env
   GEMINI_API_KEY=ваш_ключ_google_gemini
   ```

4. **Запустіть сервер:**
   ```bash
   uvicorn main:app --host 0.0.0.0 --port 8000 --reload
   ```

## Доступні API Ендпоінти
- `GET /health` — перевірка статусу сервера.
- `POST /api/eco-mode` — генерація ШІ-рекомендацій для прання.

**Приклад запиту:**
```json
{
  "fabric_type": "бавовна",
  "color": "Світлий",
  "dirt_level": "Середній",
  "weight_kg": 4.0
}
```

**Приклад відповіді (`200 OK`):**
```json
{
  "temperature": 30,
  "spin_speed": 800,
  "duration_minutes": 50,
  "detergent_ml": 45,
  "ai_explanation": "Для 4 кг світлої бавовни обрано помірну кількість еко-засобу та оптимальний час циклу при 30°C для збереження волокон і економії енергії."
}
```

Swagger UI доступний за адресою: `http://localhost:8000/docs`

## Інструкція із запуску (Mobile)
1. Відкрийте проєкт в Android Studio.
2. Переконайтеся, що комп'ютер та Android-емулятор (або фізичний пристрій) знаходяться в одній мережі, а в `ApiClient.BASE_URL` (у файлі `MainActivity.kt`) вказана актуальна локальна IP-адреса сервера.
3. Натисніть **Run** (`Shift + F10`) для запуску застосунку.

## Обмеження поточної версії
- **Синхронізація бази даних:** історія прань зберігається локально на пристрої у SQLite (`dormwash_history.db`); хмарна БД (Supabase) і синхронізація між пристроями плануються на наступних етапах.
- **Авторизація:** вхід через корпоративну пошту `@lpnu.ua` ще не реалізовано.
- **Мережа:** бекенд працює локально, тому при зміні Wi-Fi потрібно оновлювати IP-адресу в клієнті; відкладені офлайн-запити (`очікує`) надсилаються вручну без фонової автосинхронізації.
